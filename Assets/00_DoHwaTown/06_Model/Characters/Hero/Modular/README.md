# 원본 호환 모듈러 캐릭터 — 8방향 기본 자세와 이동

승인된 정면 모듈러를 기준으로 South, SouthEast, East, NorthEast, North, NorthWest, West, SouthWest를 제작했습니다.
정면의 보이는 픽셀은 원본 일체형과 동일합니다. 나머지 방향은 같은 캐릭터의 PixelLab 회전 결과를 공통 원본 팔레트로 정리하고, 부위를 분리하고 가려진 면을 보완했습니다. 후면 머릿결에는 계단형 명암을 추가했습니다.

## 제작 규격

- 방향당 9개 레이어, 총 72개 PNG
- 공통 캔버스 100×100. 기존 정면 94×100은 좌우에 투명 3픽셀씩만 추가했습니다.
- 피벗 (0.5, 0.1), PPU는 원본 SouthIdle00 값 (약 44.70588)
- Point, 밉맵 없음, 압축 없음, Full Rect
- 모든 레이어 로컬 위치 (0, 0, 0). 방향별 발 위치를 정수 픽셀로 정렬했습니다.
- 좌우는 별도 방향 이미지입니다. 비대칭 머리 장식을 단순 좌우 반전하지 않습니다.

## 코디 슬롯

| 레이어 | 슬롯 |
|---|---|
| BackHair / FrontHair | Hair (이 순서) |
| Body | 항상 표시 |
| Boots | Boots |
| Bottom | Bottom |
| Top / SleeveLeft / SleeveRight | Top (이 순서) |
| Ornaments | Ornaments |

소매 끝 분홍 장식은 소매에, 머리 꽃과 리본은 Ornaments에 포함됩니다.
SleeveLeft/Right는 정면에서 보이는 좌우를 기준으로 한 고정 부위 이름입니다.
후면에서는 뒷머리가 몸과 의상을 덮습니다. 측면에서는 먼 쪽 소매가 몸 뒤에 위치하도록 SetFacing이 레이어 순서도 함께 변경합니다.

## 사용

프리팹: `Assets/00_DoHwaTown/03_Prefabs/B_Characters/ModularHero.prefab`

- `SetFacing(AvatarFacing.East)`: 방향 변경
- `SetEquipped(AvatarSlot.Top, false)`: 상의와 양쪽 소매 함께 해제
- `SetSlotSprites(slot, direction, sprites)`: 지정 방향의 코디 레이어 교체
- `SetSlotSprites(slot, sprites)`: 현재 방향만 교체

새 코디는 8방향 각각 등록해야 합니다. 교체 스프라이트는 같은 캔버스·피벗·PPU를 사용합니다. 방향을 바꿔도 슬롯의 표시 상태와 등록된 교체 이미지는 유지됩니다.
컴포넌트 컨텍스트 메뉴의 `방향`과 `미리보기`에서도 확인할 수 있습니다.
`DoHwa/Create Modular Character Prefab`은 현재 PNG에서 기본 프리팹을 다시 만듭니다.

## 이동 애니메이션

`Motions/{방향}/{Walk|Run|Dash}/{부위}.png`는 100×100 프레임 8개를 세로로 담은 100×800 시트입니다.
216개 시트에 총 1,728개 부위 프레임이 있으며, 9개 부위를 합치면 192개의 완성 동작 프레임입니다.
기본 자세 8개는 기존 방향 폴더에 그대로 있습니다.

승인된 모듈러의 픽셀과 팔레트를 공통 관절 동작에 맞춰 재배치하고 PixelLab의 픽셀 도구로 프레임을 제작했습니다.
몸·소매·신발이 같은 관절 동작을 사용하며 머릿결에는 별도 지연 움직임을 적용했습니다.
프레임 사이에 보간하지 않고 Point 샘플링으로 교체합니다.

| 동작 | 프레임 | 재생 |
|---|---:|---|
| Walk | 8 | 10 fps, 반복 |
| Run | 8 | 12.5 fps, 반복 |
| Dash | 8 | 기본 25 fps, HeroMotor의 실제 대시 시간에 맞춰 재생, 반복 안 함 |

`HeroRig.prefab`과 `HeroPlayground.unity`의 캐릭터는 모듈러 재생 경로로 연결됐습니다.
기존 SpriteVisual 아래 모듈러 프리팹을 붙여 카메라 정렬을 그대로 이용합니다. 그 위치의 기존 일체형 Renderer/Animator는 비활성화했습니다.
WASD/방향키 이동, Shift 달리기, Space 대시입니다. 패드는 왼쪽 스틱/오른쪽 트리거/아래쪽 페이스 버튼입니다.
실제 이동량이 줄면 보행 재생 속도도 줄고, 방향 전환과 걷기↔달리기 전환은 발 주기를 유지합니다.

### 움직이는 코디 교체

- `Animate(direction, motion, deltaTime, playbackRate)`가 모든 레이어를 하나의 시간으로 진행합니다.
- `SetSlotAnimation(slot, direction, motion, sprites)`로 해당 동작의 부위 프레임을 교체합니다.
- 배열은 프레임 순서이며, 각 프레임 안에서는 슬롯의 레이어 순서입니다. Top이면 `[상의0, 왼소매0, 오른소매0, 상의1, ...]`의 24개입니다.
- `SetSlotSprites`는 기본 자세만 교체합니다. 새로운 코디는 기본 자세와 Walk/Run/Dash의 8방향을 모두 등록해야 합니다.
- `SetEquipped`의 표시 상태는 방향과 동작이 바뀌어도 유지됩니다.

시트 슬라이싱은 공식 `com.unity.2d.sprite` 패키지의 데이터 프로바이더로 처리했습니다.

## 검증 (2026-10-03)

Unity URP 격리 렌더에서 8방향 각각 기준 합성 이미지와 RGBA 차이 0픽셀을 확인했습니다.
방향 전환 후 의상 해제 상태(4개 레이어), 몸체만 표시(1개 레이어), 방향별 교체 스프라이트 유지도 확인했습니다.
빌드는 실행하지 않았습니다.


### 이동 검증 (2026-10-03)

- PixelLab 레이어 재합성 192프레임과 Unity URP 실제 렌더 결과의 픽셀 차이 0.
- 프레임 누락, 의상 해제 유지, 방향 전환 시 보행 주기 유지, 걷기→달리기 주기 유지, 대시 끝 프레임 정지 확인.
- Play Mode 가상 키보드: 동시간 걷기 약 0.81 / 달리기 약 1.56 유닛 이동, 대시 진입, 입력 해제 후 정지, NW 대각선 전환 및 상의 해제 유지 확인.
- 빌드는 실행하지 않았습니다.


### 걷기 재생 순서 보정

Walk 시트의 원본 인덱스는 `0,7,6,5,4,3,2,1` 순서로 연결합니다. 원본 순서는 발이 떠 있는 동안 뒤로 이동해 뒷걸음처럼 보였기 때문입니다.
모든 코디 레이어를 함께 재배열하며, 외부 `SetSlotAnimation` 입력은 실제 재생 순서대로 전달합니다.

### 달리기 다리 보정

Run은 발 회수 구간을 바로잡은 새 프레임을 사용하므로 원본 인덱스 0→7 정순으로 재생합니다.
기존 부츠를 잘라 변형하던 방식 대신 몸체의 허벅지와 부츠의 무릎·정강이·발 윤곽을 각 프레임에 다시 그렸습니다.
8방향 64프레임의 부츠에서 고립 픽셀 조각이 없고, 한두 개의 연결된 다리 윤곽을 유지하는 것을 검사했습니다.
실제 교체한 에셋은 Run의 Body/Boots 시트 16개이며, 나머지 7개 레이어는 픽셀 단위로 동일합니다.
Unity URP 재합성과 코디 유지 검증을 통과했습니다. 빌드는 실행하지 않았습니다.
